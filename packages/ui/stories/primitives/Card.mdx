# Card

## 1. Purpose

Groups the information and actions about one topic on a page, so the user sees where one topic ends and the next begins.

## 2. When to use

| Situation in DevMentor | Source |
| --- | --- |
| The /account panels: account data, GitHub connection, sign-out | E01-S01 spec |
| The booking summary next to the payment step: mentor, slot, price, terms | E03-S02, R08, R27 |
| One settings group on an operator screen (fee, price bounds) | R28, R29, R35 |

## 3. When not to use

| Instead of a card… | Use | Source |
| --- | --- | --- |
| Rows of a list (mentors, sessions, invitations) | Table or list rows divided by lines | R01.1, R01.3, K1 |
| A card inside a card | One card with sections separated by `Separator` | What to avoid |
| Three identical cards with icons on a landing page | Nothing; marketing uses plain text | A01, P11 |
| A message in the session | Message (Product/E04): the conversation has no boxes | R02.1 |

## 4. Anatomy

| Part | Optional | Notes |
| --- | --- | --- |
| Container | no | `border-border`, `rounded-lg`, no shadow |
| `CardHeader` | yes | `CardTitle` (semibold), `CardDescription` (muted) |
| `CardAction` | yes | Top right of the header: a badge or a small button |
| `CardContent` | no | Main content |
| `CardFooter` | yes | Muted strip for the closing action and its explanation |

## 5. Variants

| Size | Choose it when |
| --- | --- |
| `default` (16 px padding, `p-panel`) | Page panels |
| `sm` (12 px padding) | Dense operator screens |

## 6. States

A card has no states of its own. It is not clickable: put a link or button inside it. Loading, empty and
error states belong to its content (Skeleton, EmptyState, ErrorMessage in batch 3).

## 7. Behaviour and accessibility

| Topic | Rule | Source |
| --- | --- | --- |
| Heading | `CardTitle` is a `div`; when the card is a page section, give it a heading level with `asChild`-free markup: wrap the title text in `<h2>` | WCAG 1.3.1 |
| Focus | Only the controls inside are focusable, in reading order | WCAG 2.4.3 |
| Screen reader | Reads the content in order; no landmark is added | — |

## 8. Content

| Rule | Example |
| --- | --- |
| Title names the topic in 1–3 words | "Konto", "Podsumowanie rezerwacji" |
| Description says why it is here | "Dane, którymi logujesz się do DevMentor." |
| Footer explains the consequence of its action | "Wylogujemy Cię na wszystkich urządzeniach." (E01-S01 spec) |

## 9. Responsive

| Width | Behaviour |
| --- | --- |
| 320 px | Full width; content and footer stack |
| 768 px | Cards may sit in two columns |
| 1440 px | Within `max-w-page`; never more than one row of two or three cards of different topics |
