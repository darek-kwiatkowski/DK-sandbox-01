# Color

Warm greys carry the interface and one warm ochre accent marks the single most important thing on a screen.
Every value lives in `packages/ui/src/styles/tokens.css`; components use only the semantic roles below.

## Rules

| Rule | Source |
| --- | --- |
| Use semantic roles (`bg-background`, `text-muted-foreground`, …). Raw palettes (`--sand-*`, `--ochre-*`, `--red-*`) exist only inside `tokens.css`. | tokeny.md |
| Greys are warm, never hue-less grey. | R01.4, P01 |
| The accent colour (`primary` or `highlight-foreground`) is on exactly one element per screen. | R01.5, K3, tokeny.md rule 3 |
| Highlight by colour **or** by weight, never both. In lists the highlighted slot is `font-semibold`; in a running session the time left is `text-highlight-foreground`. | R01.5, K3, P02 |
| Colour is never the only carrier of meaning: an error has text or an icon, a status has a label. `primary` and `destructive` differ in luminance by only 1.11 : 1. | WCAG 1.4.1 |
| `accent` is the shadcn name for a hovered row or menu item, not the brand colour. The brand accent is `primary`. | tokeny.md |
| No gradients, glass or glow, and no violet. | A01, P11 |
| Every role has a light and a dark value; check both. | tokeny.md rule 12 |

Ratios below are computed in your browser from the resolved CSS variables of both themes (WCAG 2.x formula).
